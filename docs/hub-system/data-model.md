## 1. 原則

1. **顧客・物件・案件**が中核。帳票・承認は案件（またはマスタ）に紐づく  
2. 案件配下の仕事は **Issue行**（工程・作業・ゲート・稟議・購買・請求…）  
3. 親子は **`parent` 参照のみ**で表現。`depth` は親連鎖から導出  
4. **一覧に出る子集合と詳細の子Issueは一致**させる（文脈行許容）  
5. 転記用の「別表の正本」を増やさない（進捗は案件の進みで共有）

---

## 2. 中核エンティティ

| エンティティ | 主な属性（要件） | モック | 本番 |
| --- | --- | --- | --- |
| 顧客 | 名義・連絡先・仮/本・部門拠点・無効 | ✅ | 永続化・名寄せ本番 |
| 物件 | 住所・構造・契約顧客・保証 | ✅ | 無効化操作 ⬜ |
| 案件（deal等） | タイトル・進み・Open/Close・担当・取引形態 | ✅ | |
| Issue（汎用行） | kind, parent, repo, status, own, body, tl | ✅ | API化 |
| 組織・社員 | 部門・拠点・ロール | 模擬 | 人事同期 |
| 商品・在庫 | SKU・単価・数量・安全在庫 | ✅ | 単価改定 ⬜ |
| 外注・提携 | 区分・保険期限・手数料率 | ✅ | 改定・無効化 ⬜ |

## 3. 案件ツリー（例: 調査案件）

```
案件 (deal)
 ├─ 工程: 引合・受付
 │    └─ 作業…
 ├─ 工程: 商談・見積
 │    └─ 作業（訪問・見積…）
 ├─ ゲート: 施工前（決裁・購買）
 │    ├─ 稟議…
 │    └─ 購買…
 ├─ 工程: 施工
 │    └─ 作業（入場・報告）
 └─ 工程: 完工・請求
      ├─ 事務タスク
      └─ 請求
```

タスク列（旧 Sub）= **直接の子**の Done数 / 総数（孫は親の進捗に直接は入らない）。

### 3.1 機械ルール（子／孫の判定）

| 概念 | 定義 |
| --- | --- |
| **子** | `parent === そのIssueの id`（直接の子のみ。`kids(id)`） |
| **孫** | 子の子（ルートから見て depth=2） |
| **`depth`** | 親連鎖の長さ。手入力しない。`insertIssue` / `normalizeIssueGraph` で導出 |
| **最大深さ** | **depth = 2** まで（ルート→子→孫）。曾孫（depth≥3）は当面禁止 |

```
depth0 ルート（deal / lead / support）
  └─ depth1 子（phase / gate のみ）
       └─ depth2 孫（task / ringi / buy / bill）
```

## 3A. 案件ツリー許可マトリクス（正典・全パターン）

kind ごとの「誰の下に何を付けるか」。機械ルール（`parent` / `depth`）とは別に、**業務上の許可**をここで固定する。モック起票もこれに揃える（乖離は §3A.7）。

### 3A.1 A. ルート（depth 0 / `parent: null`）— 台帳の「案件行」

| ID | kind | 意味 | 子を持てるか |
| --- | --- | --- | --- |
| R1 | `deal` | 案件（活動が案件化した幹） | 必須（工程・ゲート） |
| R2 | `lead` | リード／活動予定（未案件化） | 任意（当面は子なし可。案件化で R1 へ） |
| R3 | `support` | 対応（クレーム等） | 任意（作業をぶら下げるなら工程経由） |

**禁止**: ルートに `task` / `ringi` / `buy` / `bill` / `phase` / `gate` を置く（単独購買の WIP は非推奨。§3A.7）。

### 3A.2 B. 子（depth 1）— ルート直下のみ許可

| ID | 親 kind | 子 kind | 役割 | 例（#841） |
| --- | --- | --- | --- | --- |
| C1 | `deal` | `phase` | 工程まとまり | 引合・受付 / 商談・見積 / 施工 / 完工・請求 |
| C2 | `deal` | `gate` | 施工前ゲート（決裁・購買の束） | 施工前ゲート |
| C3 | `lead` | `phase` | （任意）活動内の工程分割 | 現状シードほぼ無し |
| C4 | `lead` | `task` | **禁止** — 作業は工程の下 | — |
| C5 | `support` | `phase` | （任意）対応の工程 | 現状シード無し |
| C6 | `support` | `task` | **禁止** — 同上 | — |

**ルート直下に付けてよいのは `phase` と `gate` のみ。**

### 3A.3 C. 孫（depth 2）— 工程／ゲート直下

| ID | 親 kind | 子 kind | 役割 | 例 |
| --- | --- | --- | --- | --- |
| G1 | `phase` | `task` | 作業（訪問・見積・入場・事務…） | 現地調査の日程調整 |
| G2 | `phase` | `bill` | 請求（完工・請求工程の下） | 請求書発行 |
| G3 | `gate` | `ringi` | 稟議（値引・着手・特例…） | ringi#12 |
| G4 | `gate` | `buy` | 購買申請 | buy#31 |
| G5 | `phase` | `ringi` | **禁止** — 稟議はゲート配下 | — |
| G6 | `phase` | `buy` | **禁止** — 購買はゲート配下 | — |
| G7 | `gate` | `task` | **禁止** — ゲートの子は決裁系のみ | — |
| G8 | `gate` | `bill` | **禁止** | — |

### 3A.4 D. 深さ・構造の制限

| ID | ルール |
| --- | --- |
| D1 | **最大 depth = 2**（ルート→子→孫）。曾孫（depth≥3）は当面禁止 |
| D2 | `phase` の下に別 `phase` / `gate` を付けない |
| D3 | `task` / `ringi` / `buy` / `bill` は葉（さらに子を持たない）。訂正稟議は**兄弟**としてゲート直下に追加（親子にしない） |

### 3A.5 E. 業務イベント → どこに生えるか（起票パターン）

| ID | 操作 | 生える場所（正典） | 結果の呼称 |
| --- | --- | --- | --- |
| E1 | 活動予定を立てる | ルート `lead` | ルート（子ではない） |
| E2 | リード→案件化 | ルート `deal` ＋子 `phase`（商談・見積等）を生成 | ルート＋子 |
| E3 | 工程内の作業完了・追加 | 該当 `phase` の下に `task` | 孫 |
| E4 | 見積作成 | 商談・見積 `phase` の下に `task` | 孫 |
| E5 | 稟議起票（値引・着手等） | 案件の **施工前 `gate`** の下に `ringi` | 孫 |
| E6 | 購買申請（施工前） | 同 `gate` の下に `buy` | 孫 |
| E7 | ゲート全子 Done | ゲート開通 → 施工 `phase` の Blocked 解除 | （親子構造は不変） |
| E8 | 請求発行 | 完工・請求 `phase` の下に `bill` | 孫 |
| E9 | 対応起票 | ルート `support` | ルート |
| E10 | 解約・売上訂正など案件横断の稟議 | 原則は対象案件の `gate` 下。ゲート未作成なら先に C2 を作る | 孫 |

### 3A.6 F. 明示的に「子／孫にしない」もの

| ID | もの | 理由 |
| --- | --- | --- |
| F1 | 顧客・物件マスタ | Issue ではない。案件が `customer` / `property` キーで参照 |
| F2 | Comment／タイムライン | Issue の履歴。別行にしない |
| F3 | 別案件どうし | 親子にしない（同一顧客・物件でも兄弟ルート） |
| F4 | リードと案件 | 変換は同一行の kind 変更 or 新 deal＋旧 lead Close（親子にしない） |

### 3A.7 既知のモック乖離（正典未準拠・別タスクで修正）

シード `#841` は正典どおり（gate 下に ringi/buy）。一方、動的起票の一部が正典と食い違う。

| 箇所（`saad-github-hub.html`） | 現状 | 正典との差 |
| --- | --- | --- |
| `addRingi()` | `parent: dealId`（ルート直下） | E5: **gate 配下** |
| 解約稟議 | `parent: root.id` | 同上（E10） |
| `FORMS.buy` | `parent: v.deal` または `parent:null` のルート購買 | E6: gate 配下。ルート購買は非推奨 |
| `parentForQuote` | 商談 phase が無ければ **deal 直下に task** | E4: 先に C1（phase）を作ってから task |

コード修正は本マトリクス確定後の別コミットとする。

## 6. 整合ルール（必須）

| ID | ルール |
| --- | --- |
| DR-01 | parent が指すIDは必ず存在する（孤児禁止） |
| DR-02 | depth は親連鎖長と一致 |
| DR-03 | 循環参照禁止 |
| DR-04 | ref（sfa#等）は一意 |
| DR-05 | 詳細の子Issue ＝ kids(parent) と同集合を一覧でも表現可能 |
| DR-06 | kind × 親の組み合わせは §3A 許可マトリクスに従う（禁止パターンを起票しない） |
| DR-07 | depth ≤ 2（曾孫禁止） |

モック実装: `normalizeIssueGraph()`（`saad-github-hub.html`）。許可マトリクスの動的起票準拠は §3A.7 参照（一部未準拠）。
