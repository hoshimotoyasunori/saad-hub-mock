## 1. デバイス方針

| 窓 | 方針 | 実装 |
| --- | --- | --- |
| PC | GitHub Issues風の**台帳**。一覧・管理・承認 | `saad-github-hub.html` |
| スマホ | **ジョブ型**（今日やること・報告・承認）。Issue語彙を主UIに出さない | `saad-mobile-hub.html` |
| 切替 | 幅820px／`?v=pc|mobile|auto` | `index.html` |

GitHub Mobileの移植は採用しない。

## 2. PC詳細パネル（確定要件）

| ID | 要件 | 状態 |
| --- | --- | --- |
| UI-P01 | 詳細は**台帳エリア内**の右オーバーレイ（ページ全体モーダルではない） | ✅ |
| UI-P02 | テーブル幅は開閉で崩さない | ✅ |
| UI-P03 | 本文｜メタの2カラム。メタ（Assignees等）は固定幅 | ✅ |
| UI-P04 | 左端ドラッグで幅変更。最小〜420px、最大エリアの**2/3** | ✅ |
| UI-P05 | 外側クリックでは閉じない。×／Escape | ✅ |
| UI-P06 | Assignees列（台帳）も固定幅 | ✅ |
| UI-P07 | 進捗表示は日本語（未着手／対応中／完了／準備中 等） | ✅ |
| UI-P14 | 台帳列語彙: 進捗／担当／経過／系統／タスク（GitHub語の Assignees・Repository・Sub・放置は出さない） | ✅ |
| UI-P08 | 一覧と詳細の子Issue集合が矛盾しない | ✅ |
| UI-P09 | 顧客・物件台帳も案件と同じ右オーバーレイ詳細 | ✅ |
| UI-P10 | 案件詳細は別画面へ遷移したら閉じる（同一台帳内の行切替は維持） | ✅ |
| UI-P11 | 顧客／物件詳細から「活動予定を立てる」（新規 or 続きから）。営業は案件作成と言わない。管理台帳では案件行 | ✅ |
| UI-P12 | 案件詳細の顧客・物件はマスタ詳細へのリンク（本文・右メタ） | ✅ |
| UI-P13 | 活動予定の顧客・物件は検索選択。きっかけはチップ＋自由入力 | ✅ |
| UI-P15 | 案件表示名は `{部門}-{年}-{活動種別}・{作業内容}（{対象}）`（連番なし）。マスタ未選択可（両方空なら仮の相手名必須） | ✅ |
| UI-P16 | 「下書き」と「自分の申請」は別画面。前者は未送信、後者は提出後の誰待ちか | ✅ |

## 5. 用語の約束

| 約束 | 意味 |
| --- | --- |
| Open ≠ 進捗 | Openは生きているだけ。進捗はStatus |
| 仕事は行 | 新しい仕事＝行を足す |
| 台帳は窓 | 実体はリポ／アプリ |
