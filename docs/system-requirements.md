## 1. 目的

本システムは、旧業務基盤・Excel・WF（総称 **ASIS**）に散在していた  
「依頼〜見積〜決裁〜購買〜施工〜請求」を、**顧客・物件・案件を中核とした一つの基幹**に寄せ、  
必要な管理を残し、多重転記などの無駄な管理をやめることを目的とする。

### 1.1 ビジネス目標

| ID | 目標 |
| --- | --- |
| BG-01 | 同じ事実の Excel／メール多重転記をなくす |
| BG-02 | 「いま誰待ちか」を一覧で見えるようにする |
| BG-03 | 営業・施工はスマホ、デスク職はPC台帳で同じデータを扱う |
| BG-04 | 承認・手配・締めのキューを用途ごとに分けつつ、案件は1本で辿れる |

### 1.2 本SRSの位置づけ

| 段階 | 本文書の役割 |
| --- | --- |
| 現在（モック） | UI合意・業務カバレッジ検証の入力。機能の多くはモックで操作確認済み |
| 今後（本番） | API・認証・永続化・連携を足すときの親要件。⬜ は [roadmap.md](./roadmap.md) で追跡 |

## 2. スコープ

### 2.1 含む（In）

- ポータル（玄関・通達・自分宛）
- 顧客・物件マスタ、案件（Issue）台帳と詳細
- 稟議・購買・施工ゲート・請求・入金・売上の幹フロー
- 保証・点検・修理・外注・在庫など管理台帳（モック導入範囲は coverage 参照）
- PC台帳UI／スマホジョブUI
- 権限モデル（ロール・スコープ）の要件定義
- 監査・変更履歴の要件

### 2.2 含まない／段階導入（Out / Later）

- 勤怠・人事ポータルの内製（外部SSO）— ➖
- 会計仕訳の最終確定（会計連携）— 後続
- ASIS全業務（約500）の画面化 — 目的外
- 実PDF印刷・本番メール・プッシュの完遂 — 後続（モックは模擬）

詳細な ✅🟡⬜ は [../asis-capability-coverage.md](../asis-capability-coverage.md)。

## 4. 前提・制約

| ID | 内容 |
| --- | --- |
| AS-01 | 組織は全国多拠点。個人×アプリの手設定は避ける（RBAC＋人事連動） |
| AS-02 | データは共有、窓（PC/スマホ）と道具（アプリ）は分ける |
| AS-03 | 現状の参照実装は静的HTMLモック（永続化なし） |
| AS-04 | ASIS根拠の型 A〜K に当ててから機能を増やす（HANDOFF参照） |
| CO-01 | 個人情報・金額はロールで見せ分け |
| CO-02 | 自己承認禁止などガバナンス要件を守る |

## 7. データ要件（要約）

詳細は [data-model.md](./data-model.md)。

- 中核: **顧客・物件・案件（Issue）**
- 案件配下: 工程・作業・ゲート・稟議・購買・請求など（`parent` 階層）
- 整合: 一覧と詳細の子集合が矛盾しないこと（モック要件 P-13/P-14）
