## 1. 目標

- 個人×アプリの手設定をしない（約1000人規模でも運用可能）
- 人事異動に自動追従
- 例外は期限付き・申請ベース

---

## 2. モデル

**RBAC ＋ 人事マスタ連動 ＋ 例外オーバーライド**

```
人事（所属・役職） → ロール → アプリ束＋データスコープ
例外申請（少数・期限付き） → 個人へオーバーライド
```

### 2.1 データスコープ（例）

| スコープ | 意味 |
| --- | --- |
| self | 自分の担当 |
| branch | 自拠点 |
| region | 担当地区 |
| division | 事業本部 |
| all | 全社（購買物流等） |

### 2.2 モックのロール例

一般営業／施工／拠点長／地区事務／管理部／購買 — UIで切替デモ。

---

## 3. 必須ガバナンス

| ID | 要件 | モック |
| --- | --- | --- |
| SEC-01 | 自己承認禁止（拠点長自身の申請は上位へ） | ✅ |
| SEC-02 | 高額・クレーム・解約は一括承認不可 | ✅ |
| SEC-03 | 代理起票は起票者と申請者を分離 | ✅ |
| SEC-04 | 不在時は代理者へInbox | ✅ |
| SEC-05 | 施工ロールは金額非表示 | ✅ |
| SEC-06 | 監査ログ | ✅ |
| SEC-07 | 例外権限の申請画面 | ⬜ |
| SEC-08 | 管理者の強制ロック解除（理由必須） | ⬜ |
| SEC-09 | 個人情報・手数料の項目別マスク完遂 | 🟡 |
| SEC-10 | 本番SSO・セッション管理 | ⬜ |
