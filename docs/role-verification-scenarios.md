### 2-1. 判定マトリクス（役割×幹シナリオ）

| 役割 | ✅ モックで通せ（推奨デモ） | 🟡 薄い／入口のみ | ➖ SSO・基幹外で通さない | ⛔ やらない（転記再現しない） |

| **技術** | 施工予定・割当／入場・完了・写真／ゲート連動／外注注文書／安全ヒヤリ／修理依頼 | 材料選定の**技術回答専用キュー**／予定の管理部報告・朝礼集約／石綿行政報告 | — | — |
| **管理部（事業）** | 登録・振分キュー／見積受付／受注確認／お客様確認電話／契約・契約稟議／請求・入金／外注承認 | 施工進捗の本部集約／返金専用台帳（通知まで） | 会計仕訳の最終確定 | Excel進捗・販路日報・日次管理・日報転記 |

### 2-2. 「通す／通さない」判定に使うチェック質問

1. **その仕事は coverage で ✅ か ➖ か？** → ➖はシナリオ文書に「SSO期待」と書き、Hub操作シナリオにしない。  
2. **gap-audit で 🟡薄いと残っているか？** → 通しデモの主シナリオにしない（副シナリオで「ここまで」と明示）。  
3. **⛔転記か？** → 「やめたことの確認」シナリオ（台帳Viewで同じ情報が見える）に回す。  
4. **誰が主担当か（仮分類／登場人物台帳）と Hub ペルソナが一致するか？** → 不一致なら「近似ロールで検証」と注記。

### 2-3. 役割横断の通しシナリオ（Hubで推奨）

`saad-hub-manual.md` §5 のピル切替デモを拡張した幹:

1. 営業: 調査依頼を管理部へ報告  
2. 管理部: 登録・振分  
3. 営業: 調査→見積→契約書WF／値引

6. 技術: 割当・完了  
7. 管理部/経理: 受注確定済案件の請求・Close  

相談室・人事・総務は **この幹の外**（入口検証 or SSO説明）に置く。

## 4. 推奨するシナリオ文書の構成案（質問4）

新ファイルを役割ごと／1冊にまとめる場合の推奨構成:

```text
role-verification-scenarios.md   ← 本書（洗い出し・索引）
role-scenarios/
  00_index.md                    ← 役割×シナリオIDマトリクス（✅🟡➖）
  01_sales.md
  02_tech.md
  03_biz_admin.md                ← 管理部（事業系）
  04_branch_manager.md
  05_ops_clerk.md                ← 事務（事業系）
  06_procurement.md
  07_accounting.md
  08_general_affairs.md
  09_hr.md
  10_customer_desk.md
  90_end_to_end.md               ← 役割横断の1本通し
```

### 各役割ファイルの章立て（テンプレ）

1. **役割定義** … 登場人物台帳の正式名称 ↔ Hubペルソナ（または近似）↔ データスコープ  
2. **ASIS仕事一覧** … §1相当（業務ID・成果物パス）  
3. **検証対象外** … ➖SSO／⛔転記を先に明示（誤解防止）  
4. **シナリオ表** … ID／前提データ／手順／期待結果／検証区分／根拠パス  
5. **画面マップ** … manual・journey・coverage へのリンクのみ（重複記述しない）  
6. **合格基準** … 「✅行がすべて通る」「🟡は既知限界を説明できる」  
7. **デモ台本（5〜10分）** … 操作ピル切替順  

### 運用ルール（案）

- シナリオIDは安定させ、実装進捗は coverage／gap-audit を正とする（シナリオ側は区分だけ更新）。  
- 新シナリオを足すとき、必ず **主担当（仮分類）か登場人物台帳** のどちらかを根拠に付ける。  
- 経理・総務・人事・相談室は **ペルソナ未実装**のため、検証前に `personas.js` へ仮ロールを足すか、「P5/T1切替＋注記」を台本に書く。
